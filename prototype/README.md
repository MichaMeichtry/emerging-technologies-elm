# IT Service Desk - Elm Prototype

An IT support ticket management system built entirely in Elm. The application allows users to create, track, and manage support tickets across their full lifecycle from submission through to resolution and closure.  
It was chosen as the prototype for this project because its domain maps naturally onto Elm's core strengths: a structured data model, clearly defined state transitions, and a user interface that benefits from strict type safety and enforced architecture.

## Requirements

- [Node.js](https://nodejs.org/) v14 or higher
- Elm 0.19.1: `npm install -g elm`

See [docs/00-setup/01-environment-setup.md](../docs/00-setup/01-environment-setup.md) for the full installation guide.

## How to Run the Prototype

The application is already compiled.  
Open `public/index.html` directly in your browser, no build step needed.

You are welcome to make changes to your local copy of the prototype to find out how the technology works and what you can do with it. If you make any changes, simply use the following command to recompile the project:

```bash
cd prototype
elm make src/Main.elm --output=public/app.js
```

Then simply refresh your browser or re-open `public/index.html` to see your changes.

> **Tip:** Install the [Live Server](https://marketplace.visualstudio.com/items?itemName=ritwickdey.LiveServer) extension in VS Code and use "Open with Live Server" on `public/index.html`. The browser will reload automatically after each `elm make` run.

## File Structure

```
prototype/
├── README.md                   # This file
├── elm.json                    # Elm project configuration and dependencies
├── package.json                # npm configuration: defines build scripts and optional dev dependencies (not used in this prototype)
├── public/
│   ├── index.html              # HTML entry point that mounts the Elm application
│   ├── app.js                  # Compiled output (regenerated by elm make, do not edit)
│   └── style.css               # Application styles
└── src/
    ├── Main.elm                # Entry point: wires together init, update, view
    ├── Model.elm               # Model record, init function, and seed tickets
    ├── Msg.elm                 # All Msg variant declarations
    ├── Types.elm               # All custom type definitions: Ticket, TicketStatus, Priority, FilterState
    ├── Update.elm              # The update function and all Msg handling logic
    └── View.elm                # All view functions and HTML rendering logic
```
